API MASHUP / PAPER PROTOTYPE

Walk or bus?

Two data sources. One everyday decision.

A concept for students and commuters in Stockholm who can either walk or take a bus on a short journey. Weather forecasts and upcoming departures come together in one simple suggestion.

Concept only. The screens below use fictional example data. No live API connection is implemented.

The two APIs

01 / WEATHER

Open-Meteo

The Weather Forecast API provides forecasts for geographic coordinates. This concept uses temperature and the probability of precipitation for the next hour at the chosen stop.

Read Open-Meteo documentation
02 / TRANSPORT

SL Transport

This API provides stops, lines and upcoming departures in the SL network. The concept uses the stop’s coordinates and the next bus in the user’s chosen line and direction.

Read SL Transport documentation

How the mashup works

  1. Choose a stop, bus line and direction.
  2. Enter your own estimate of walking time to your destination.
  3. Retrieve the next relevant departure from SL Transport and use the stop’s coordinates to request the local forecast from Open-Meteo.
  4. Combine the two responses into a suggestion, with the weather and waiting time shown alongside it.

The bus route is selected by the user. This concept does not calculate a route or total bus journey time.

Paper prototype

Two static mobile screens showing the proposed journey. All values are illustrative.

Simple decision rules

Take the bus

Precipitation probability is at least 60% and a relevant bus leaves within 10 minutes.

Walk

Precipitation probability is below 30%, temperature is 10–25 °C and the estimated walk is no longer than 20 minutes.

Compare your options

In other cases, show the forecast, next departure and walking estimate so the user can decide.

These thresholds are design choices for the prototype, not rules supplied by the APIs.

Scope and limitations

This is a paper prototype, not a built or tested integration. It does not calculate walking routes, total bus travel time or whether the user can reach the stop before departure. If either API is unavailable, the service would show an error and offer a retry instead of giving a suggestion based on incomplete data.

Why combine these sources?

Weather describes the conditions for walking; departure data shows whether a bus is available soon. Combining them provides context for a decision that neither source can support on its own.
